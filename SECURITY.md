# Security boundaries

The default Pages deployment is a public browser application, with Google/Firebase identity and a private Firestore access directory. The roster is protected by the included rules; unapproved users cannot list addresses or grant themselves access. App code, brand assets and public Firebase selectors remain visible. Client-side gating can be bypassed in a copied/modified app, and revocation cannot erase local files or prevent use of copied code. There is no shared material library or server-held OpenAI key in this mode.

OpenAI visit keys are held in page memory only and sent directly to its fixed HTTPS endpoint with no redirect forwarding, persistence or automatic retries. In Pages AI mode, text briefs, brand requirements, assigned event photos and every uploaded logo go to OpenAI. Image revisions send original references and feedback; old generated images are never uploaded as references. The model integrates the logo references; logo and people fidelity need human review. Per-frame vision planning also sends all original logos and the single assigned photo to Chat Completions. Only bounded planning previews are sent there; original files go to image edits. Source bindings are controlled by the app, never by model output. Public writing research uses a separate Responses/web-search request with only whitelisted format IDs and the date, never the event, files or identity. Search evidence is untrusted input, domain-filtered, bounded and kept separate from event facts. Chat Completions and research Responses requests use `store: false`; Images API requests do not support that flag. No zero-retention promise is made. Firebase receives sign-in identities and the private roster, not event content/keys. Provider retention remains governed by its terms. Generate only with materials you are authorized to send to that provider. Approval is stored locally as review metadata; it gates ZIP export in the normal app but is not a signed audit or access-control boundary. Changing a caption or submitting visual feedback revokes its approval, and a new image version always requires approval again. UID-separated IndexedDB libraries prevent normal account mix-ups, not malicious access to an unencrypted browser profile. Use separate browser profiles on shared devices.

The remaining sections describe the **optional corporate Java mode**, not the Pages runtime.

Corporate mode authenticates Google Workspace accounts and enforces an exact-email access directory on the server. Only the configured owner can list, grant or revoke colleagues. Addresses and the private audit trail are encrypted on the persistent server disk; no real roster, domain or secrets are committed or published. Invitations are manual link sharing, with no email service integration.

Approved colleagues share the entire library and may view, edit, delete and export it. Record versions reject conflicting edits; finished runs are immutable, and only their creator updates active runs. Access revocation prevents future server requests. It cannot recall downloaded ZIPs, screenshots or already rendered content. This MVP has no fine-grained project permissions, DLP or remotely erasable files.

The company OpenAI key stays in the server runtime, is never returned to the browser, and is not included in projects or ZIPs. Client-supplied keys are disabled in corporate mode. Only event text, copy requirements and the shared brand policy go to OpenAI; original logos/photos remain between the approved browser and private server. Review the provider's contract, retention and organization settings with your company before entering confidential text.

Private records and binary images use AES-256-GCM authenticated encryption with random IVs and record-bound contexts. Storage paths are validated UUIDs and are never publicly served. The application verifies image signatures, limits upload sizes, and encrypts streamed uploads without plaintext multipart temporary files. AES protects the disk/backups; trusted hosting administrators and a compromised running application can still access plaintext and runtime keys. Store the original encryption key separately from disk backups. Wrong or missing keys fail closed; automatic key rotation and recovery are not implemented.

Corporate mode uses secure HttpOnly SameSite=Lax session cookies, CSRF verification for writes/logout, fixed HTTPS OAuth callbacks, private no-store responses, restrictive same-origin CSP and no-referrer headers. Idle sessions last 30 minutes; Google ID-token expiry and a maximum 8-hour authentication age also limit sessions. Logging must remain free of request bodies, authorization headers and query strings at both application and ingress. No analytics or external CDN scripts are loaded.

Quotas limit stored data and daily AI attempts per account/team, persisted across restarts. They do not replace OpenAI project budgets, ingress traffic limits, infrastructure monitoring, backups or human review. The single-process MVP needs one replica and a POSIX persistent disk. Browser rendering/generation requires an open page; abandoned runs are interrupted after 15 minutes without progress, keeping saved outputs.

GitHub Pages uses the separate browser-only mode described above. Development and legacy `hosted` profiles remain for contributor compatibility and are unauthenticated; never use them with company data. The default container requires corporate mode. No production host, Google OAuth registration or live provider access is created by committing this code. Follow [Deployment](DEPLOYMENT.md) and complete the private acceptance checks before inviting colleagues.
