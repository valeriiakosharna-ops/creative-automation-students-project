JAVA BACKEND + DATABASE

Creative Automation

Build a Java-backed platform that turns an event brief and original brand assets into approved social visuals and captions. Studio is a visual reference only; its browser-based architecture is not the student backend architecture.

01

MVP requirements

  • Backend and storage

    Build a Java backend with a database. Store users, projects, briefs, files or file references, generation history, captions and approvals on the server. Saved work must survive refresh and service restarts.

  • Access and shared library

    Provide sign-in, administrator-managed access and user roles. All admitted colleagues can browse the shared project library, search/filter projects and open their assets, results and history. Enforce permissions in the backend.

  • Event brief

    Collect the title, description, schedule, optional location/link, visual direction and brand colors. Support one date, a range, several dates or a written schedule. Allow uploading logos and optional event photos.

  • Output selection

    Support Instagram posts, Instagram Stories, Facebook and Google Chat. Require English, Ukrainian or both. Set a separate frame count for each format; show the total before generation. A carousel or Story sequence has one shared caption per language.

    Try it: frame counts and photo allocation

    Instagram example. This demo makes no AI requests and saves nothing.

    Each photo can be used once in English and once in Ukrainian. Every frame includes all logos.

  • Three AI requests

    Use exactly three prompt templates: a JSON visual plan, post text generation and visual generation. Send them as separate API requests. Planning and caption generation can run in parallel; image generation uses the completed plan. Keep the templates in backend files in the MVP.

            Original assets and visual quality
            
    
              Use every uploaded logo on every visual and at most one assigned
              original photo per frame. Use each photo once per network and
              language in a run. English and Ukrainian versions may reuse the
              same photos; Instagram posts and Stories share a pool within each
              language. Extra frames are information-only. Use light backgrounds
              and a coherent brand style; do not invent people or add a
              promotional call to action.
            
    
          
    • 
          
  • 
            Preview and approval
            
    
              Show ordered visuals and one editable shared caption per
              post/language. Allow manual caption edits without an AI request.
              Require approval of every visual and caption before export.
            
    
          
    • 
          
  • 
            Delivery
            
    
              Download approved visuals and post text as a ZIP. Also support
              saving the approved pack to a Google Drive folder selected by the
              user, with permission checks and useful file links. Keep project
              metadata in the database, not in Drive folder names.
            
    
          
    • 
          
  • 
            History and failures
            
    
              Preserve briefs, results and versions in the shared library. Show
              generation progress and clear errors. Keep successful results
              after a partial failure; retry only failed requests when
              explicitly requested. Show paid request counts and avoid duplicate
              submissions or hidden retries.
            
    
          
    • 
          
  • 
            Security and delivery quality
            
    
              Keep provider keys and Drive credentials protected on the backend;
              exclude them from frontend code, logs and exports. Protect all
              project files. Deliver documented APIs, database migrations, tests
              with mocked AI responses and clear setup instructions. Use English
              for the interface and documentation.
