THE USER JOURNEY

From an event
to a content pack.

  1. Create a project

    Name a folder, then start an event brief inside it.

  2. Add context & assets

    Describe the event, upload images, and set the palette.

  3. Choose the outputs

    Select channels, formats, languages and a frame count for each format.

  4. Generate & review

    Preview images and editable post texts. Submit feedback to regenerate one visual; approve every item.

  5. Export & revisit

    After every visual and post is approved, download a ZIP. Find the brief and versions in history.

Human review stays in the loop.
Nothing is published automatically.
01 The event brief+

Required: project, event title, description, date, time zone, at least one uploaded logo, at least one output format, an explicit choice of English, Ukrainian, or both, and a frame count per format and language. Dates may be one date, a start/end range, several dates or a concise free-text schedule.

Optional: event time, venue or link, tone (default: friendly), call to action, audience, event photos, visual direction, and a palette of #RRGGBB colors.

Show upload type/size limits before selection. Include every uploaded logo in each visual and require users to review logo accuracy. Support PNG/JPEG images; add other formats only when safely handled. Validate on both client and server. Never silently invent missing event details.

02 Channels & formats+

Use a multi-select: Instagram post, Instagram story, Facebook post, Google Chat message. A user can select several at once.

Instagram post1080 × 1080 · caption
Instagram story1080 × 1920 · brief overlay
Facebook post1200 × 630 · post copy
Google ChatMessage + optional image

These are project defaults, not universal platform limits. Confirm current channel rules during discovery. Set frame counts independently per selected format and language. For example, 4 Instagram feed frames + 2 Story frames, in 2 languages, produce 12 visuals. Feed frames form one carousel per language with one shared caption; Stories form a connected sequence. Language selection is required: English, Ukrainian, or both.

03 Projects & history+

Project folders group briefs and generation runs. Save the exact input snapshot, asset references, selected formats, prompt/model version, timestamps, status, errors, and output files for every run.

Regeneration creates a new run; it never overwrites past results. Users can rename projects, reopen earlier runs, and delete their own projects with confirmation. Define whether deleting a project also deletes its files.

Each uploaded photo can appear at most once per social network within a run, across all variants and languages. Instagram posts and stories share one allocation pool. A photo may be reused on a different network. When photos run out, produce information-only visuals with all logos. Record photo assignments in the manifest and test the rule. A project folder is an application concept. It does not need to correspond to a Google Drive folder.

04 Delivery & downloads+

MVP: preview generated visuals and editable post texts in the browser. Each visual has feedback, regeneration and approval controls. Revisions use the previous visual, assigned source assets, storyboard and brand policy in a new image request. Text edits are local. ZIP export requires every requested visual and post to be complete and individually approved; it contains ordered PNGs, a combined UTF-8 posts.txt, per-post text files and a manifest. Record versions and reset approval whenever content changes.

Extension: connect Google Drive, choose a destination folder, and export there. Use user-consented OAuth, least-privilege scopes, and securely stored refresh tokens. Handle access revocation and upload failures.

A Drive folder link alone does not grant upload access. Automatic posting to social networks is outside this project’s MVP.

Treat generation as a job
Persist state transitions. Track every output independently, so a failed story does not erase a successful post.
QUEUED→RUNNING→COMPLETED
Also support PARTIAL and FAILED. Retry transient failures with bounded backoff; respect rate limits. Use an idempotency key to prevent duplicate jobs on double-click.
Start with a bounded Java executor and persisted jobs. Define recovery after a server restart. A dedicated queue can come later.

        
◇
Keep brand details accurate
Use a text API (for example, OpenAI) to return structured copy, then an image generation or editing API for visuals. A ChatGPT subscription is not an API integration.
Models may distort logos, text, dates, or colors. Use a common creative identity and clear source references. Let the image model compose the full visual organically; inspect logos, typography and facts before approval. Avoid appending another logo block to already branded model output.
Choose a supported model after checking input formats, pricing, image sizes, and API access. Crop or render to your final channel dimensions.

        
Build trust into the workflow
Keep shared owner API keys on the server, in secure environment settings. Never commit keys, bundle them in JavaScript, or expose them in logs. A bring-your-own-key browser mode may send each visitor’s key directly to the approved provider over HTTPS, keeping it only in page memory. Never persist it or fall back to a shared owner key.
Validate file signatures and sizes, sanitize filenames, limit requests, and check project ownership on every operation. Agree on consent, retention, and deletion for event photos before sending them to an AI provider.
The free Pages MVP uses Google sign-in, a private owner-managed access list and separate local libraries. Its code remains public; client-side gating cannot protect a shared company key or erase local files. The optional corporate Java deployment adds a private shared library and server-side cost controls.

Where does it run?
This brief is a static GitHub Pages site. The students’ full product needs a hosted backend, database, and file storage. The free working MVP runs in the browser on GitHub Pages, with Google sign-in through Firebase and local projects per account. Users enter an OpenAI key for the visit; event text and assigned image/logo references are sent directly to OpenAI for separate planning, image generation and post-writing stages. Results are reviewed and individually approved before ZIP export. The owner manages a private list of approved Google emails. A separate corporate Java deployment supports an encrypted shared server library. GitHub/GitLab Pages alone cannot execute the AI server.

06 / THINK LIKE A PRODUCT TEAM
Ask better questions.
Build a better tool.
Business analysis turns “it generates posts” into a product with clear expectations and meaningful trade-offs.
“As an event organizer, I want to generate a consistent pack for several channels, so I can spend less time preparing the same announcement.”
01
Make success measurable
Compare time from brief to approved pack with the manual baseline. Track first-pass approval, brand accuracy, and cost per accepted output. Agree on target values with your user.
02
Define the awkward cases
No logo? Missing date? Unsupported image? A failed API? A revoked Drive connection? Decide which cases block a run, use a default, or allow partial delivery.
03
Make cost visible
Preview the output count before submission. Cap variants, explain regeneration cost, and confirm large requests. A retry must not quietly create duplicate charges.
04
Keep people in control
Generated content is a draft. Show the input, output, and version together. Allow review and a new run, and explain which data is sent to external services.


    
TURN STORIES INTO TESTS
What does “working” mean?
01 / MULTIPLE FORMATS
The count matches the request
Given a valid brief with 4 feed frames, 2 Story frames, and 2 languages, when generation completes, then the user sees 12 ordered visuals and 4 shared post captions with the correct format and language labels and can preview each one.
02 / DURABLE HISTORY
A new run keeps the old one
Given a completed run, when the user changes the palette and regenerates, then both runs retain their own inputs and files, including after a server restart.
03 / PARTIAL SUCCESS
A failure has a way forward
Given that 1 of 6 outputs fails, when the run finishes, then the user sees five successful previews and a clear failure. ZIP stays blocked until the failed image is recovered and every visual and post is approved.
