01 / BUILD THIS FIRST

A complete, useful MVP.

Build the backend in Java and persist product data in a database from day one. Start with personal projects and ZIP delivery; team collaboration comes later.

Studio is a visual example only. It demonstrates a possible interface and user journey. Its browser storage and direct AI calls are not the student architecture. Your MVP requires a Java backend, database and protected server file access. Google Drive is optional.

Access & projects

  • MVP-01Authenticated personal workspace

    Authenticate users and enforce project/file permissions in the Java backend. Start with personal projects and owner-managed product access.

  • MVP-02Mandatory database and durable history

    A database is mandatory. Persist ownership, briefs, assets, runs, captions, approvals and versions. Work must survive refresh, another device and backend restarts.

The event & assets

  • MVP-03Complete event brief

    Require a title, description and schedule. Support a single date, range, date list or written schedule, with optional location, time and link.

  • MVP-04Brand assets

    Upload 1–8 logos and up to 20 optional photos. Validate image type and size on the server; allow removal and palette selection.

The content request

  • MVP-05Formats, languages and quantities

    Select Instagram feed/Stories, Facebook and Google Chat independently. Choose English, Ukrainian or both, and 1–10 frames per format/language, up to 24 total.

  • MVP-06One story, one shared caption

    Each format/language is one ordered post or Story sequence with one shared caption. Show visual and caption counts before generation.

Visual identity & sources

  • MVP-07Original assets and people

    Every visual uses all logos and at most one assigned photo. Never repeat a photo within a network/run or request invented people. Extra frames are information-only.

  • MVP-08Coherent creative direction

    Use light backgrounds, brand colors and a consistent campaign identity. Adapt layouts naturally by channel. No automatic promotional call to action.

Generation & approval

  • MVP-09Backend AI orchestration

    Java orchestrates versioned campaign, caption and frame prompts. Each frame planner and image request receives all logos and only that frame’s assigned photo.

  • MVP-10Review before export

    Preview everything. Edit shared captions without AI calls and request paid revisions per image. The server permits ZIP export only after every item is approved.

Delivery, costs & privacy

  • MVP-11Useful ZIP delivery

    Deliver ordered PNGs, one text file per post/language, combined posts.txt and metadata. Exclude source uploads and credentials from the delivery ZIP.

  • MVP-12Recoverable failures and visible costs

    Preserve successful results and paid planning responses after partial failures. Make retries explicit, show status and cost, and avoid blocking editorial length limits.

  • MVP-13Provider keys and private data

    Keep service keys in protected backend configuration. Authorize project/file access and exclude credentials from frontend bundles, business data, logs and exports.

  • MVP-14Practical post copy

    Adapt factual captions to each channel and language. Preserve full URLs. Suggested lengths guide writing; fresh trend claims require source-backed research.

Java backend & API

  • MVP-15A Java service with a clear API

    Build a Java backend with a documented API, server validation, database migrations and database integration tests. Studio is only a visual example.

A concrete request

4 Instagram feed frames + 2 Story frames × 2 languages = 12 visuals and 4 shared captions. Frames tell a connected story; a caption belongs to the post, not to each frame.

02 / THE NEXT RELEASE

From a personal tool
to a team product.

Extend the Java backend and database you already built. Add team collaboration and administration. Google Drive is a separately selectable extension, never a replacement for the database.

Shared team workspace

  • FULL-01Shared team library

    Extend the existing MVP database with project sharing and team membership, so colleagues use the same permitted library across devices.

  • FULL-02Roles and project permissions

    Add owner, administrator, editor and viewer roles. Enforce a clear permission matrix for generation, editing, approval, export and administration.

  • FULL-03A usable team library

    Provide searchable cards/lists, useful filters, tags, archive/restore and clear statuses. Keep each project’s brief, visuals, captions and history together.

Optional Google Drive extension

  • FULL-04Google Drive connection and folder picker — optional

    Optional: connect Google Drive and choose a writable destination folder per project/export. Show the selected folder and explain ownership.

  • FULL-05Reliable Drive delivery — optional

    Optional: upload approved deliverables, save file IDs/links in the database and retry without duplicates. Keep ZIP available if Drive delivery fails.

  • FULL-06Secure Drive credentials — optional

    Optional: protect OAuth callbacks and encrypted refresh tokens. Support disconnect/revocation and verify folder access before every delivery.

Administrator prompt tools

  • FULL-07Administrator prompt editor

    Give administrators a prompt editor with variable checks, preview, explicit paid tests and publish/rollback. Keep access and source protections outside editable prompts.

  • FULL-08Versioned prompt governance

    Record an immutable prompt version on each run. Audit changes; published edits affect new work without changing historical results.

Protected operations

  • FULL-09Private managed generation

    Extend the Java service with organization-level credential management, role-based budgets, concurrency limits and cost reporting.

  • FULL-10Durable jobs and collaboration

    Persist jobs, prevent duplicate submissions/exports and handle concurrent edits. Preserve earlier versions and reset approval when relevant content changes.

  • FULL-11Private files and reliable operations

    Add retention policies, tested backups/restoration, protected file delivery, monitoring and audit records without secrets or confidential content in logs.

  • FULL-12Team onboarding and administration

    Provide team onboarding, access administration, usage visibility, ownership transfer and documented support and recovery procedures.

Drive stores deliverables. The database organizes the product.

Keep project records, permissions, prompt versions, approval state and export jobs in the database. Save file IDs and destination links there. A Drive folder is not a replacement for a shared project database.

03 / HOW THE PARTS WORK TOGETHER

Plan. Generate. Review.

Separate responsibilities so text, planning and image failures can be handled without losing the rest of the work.

  1. 1

    Event brief

    Validate facts and counts. The Java backend allocates photos and saves their assignments so a model cannot swap the original sources.

  2. 2

    Parallel preparation

    Create the shared campaign outline and channel-specific captions independently.

  3. 3

    Per-frame planning

    Inspect all logos and only the assigned photo. Plan that frame’s contribution to the story.

  4. 4

    Image generation

    Send the frame plan and those same original references. Keep the paid result for preview.

  5. 5

    Human approval

    Edit captions, revise individual images and approve every item. Export after approval.

Technical direction for Java and JavaScript students

Java owns permissions, database access, file access, AI requests, generation status, approvals and export from the MVP. Spring Boot and PostgreSQL are recommended. Provide a database schema, migrations, documented API and database integration tests. JavaScript provides the interface and previews. GitHub Pages cannot run the backend or database. Use mocked AI responses, never paid keys in CI.

04 / DEFINITION OF DONE

Show behavior,
not just screens.

Use these scenarios in the demo. The complete specification contains numbered acceptance cases for both releases.

MVP / CONTENT

The request matches the pack

Demonstrate independent counts, both post languages, correct dimensions, ordered frames and one shared caption per post.

MVP / ORIGINAL ASSETS

Every source has a purpose

With 3 photos and 6 Instagram frames, use each photo once and make the rest information-only. Every frame includes all logos. Review people and logo fidelity.

MVP / REVIEW & COST

A revision affects one image

Revise one frame without rerunning the campaign. Edit text without an API call. ZIP becomes available only after all content is approved.

MVP / DATABASE + RECOVERY

One failure does not erase success

Restart the Java service and reopen the project on another device: history remains. Simulate one failed image request; preserve successful results and retry only deliberately.

FULL PRODUCT / COLLABORATION

A team can trust its library

Open the same project on another device. Verify role permissions, protected file access, conflict handling, durable history and backup restoration.

FULL PRODUCT / PROMPTS + OPTIONAL DRIVE

Drive and prompts are controlled

Publish and roll back a prompt as admin; prove an editor cannot do it. If the Drive extension is chosen, select a folder and recover from revoked access without regenerating content.

05 / IMPLEMENTATION MILESTONES

Build in useful increments.

  1. Understand the organizer

    Agree on the workflow, MVP scope, acceptance examples and cost expectations.

  2. Deliver one vertical slice

    Java service + database, one persisted project, one format/language, preview, approval and ZIP. Develop with fake assets and provider mocks.

  3. Finish and verify the MVP

    Add counts, languages, photo allocation, per-frame planning, revisions, database-backed history and failure recovery. Verify persistence after a backend restart.

  4. Hand over, then expand

    Document setup and limits. Measure time to an approved pack and actual cost. Extend the existing database and backend with the team library and prompt administration. Add Drive only if selected.

Not in this assignment: automatic social publishing, video generation, subscriptions, unattended bulk campaigns and analytics dashboards, unless separately agreed.
